## Evidence per claim

### 1. Live in-tab training through the phase change

- Sequence Toy + Piston (README read via `gh api`, repo created 2025-01-16, last push 2025-12-03). The README describes "a web playground for training sequence models (Transformers, LSTMs, GRUs, and vanilla RNNs) using Piston, a proof-of-concept WebGPU automatic differentiation library." The repo ships a `Repeat` toy task ("Repeat a sequence of characters", up to 10 items over up to 26 symbols, in `examples/piston-train-toy/src/lib/train/data/toy/repeat.ts`) and a visualizer whose examples select attention probabilities and their gradients per layer (`visualizationExamples.ts`). A viewer can already watch attention patterns form on a copy task during in-browser training. Nothing read there mentions induction heads, previous-token heads or a phase change.
- The author's blog (https://vin.how/blog/train-a-language-model-in-your-browser) claims priority for the general capability: "But, to my knowledge, Piston is the first project that combines enough compute shaders and WebGPU performance considerations in one place to train something as involved as language models, albeit at a small scale, in a web browser". It also credits ConvNetJS, TensorFlow Playground, TensorFlow.js and webgpu-torch as earlier browser training.
- Little Language Machine, arXiv 2601.21631 (full text read). It trains a small transformer client-side ("Training and inference are hardware- accelerated through WebGPU or WebGL"), and "Within minutes, the model progresses from random character noise to increasingly coherent text sequences". The word "induction" appears 0 times in the full text.
- TabGPT (README read, created 2026-08-16) pretrains a GPT in a tab and shows live loss and samples. No circuit view.
- Negative results. Two web searches for a live in-browser induction-head trainer returned only the papers and a course walkthrough. GitHub repo searches for "induction heads browser" and "train transformer in browser" returned 0 repos. The top-starred "induction head" repos are all PyTorch or TransformerLens notebooks.
- Not individually checked: Transformer Explainer, bbycroft LLM Visualization, TensorFlow.js examples, ONNX Runtime Web training, Observable notebooks, surfgrad, TinyGPT, jax-js. From prior knowledge (not re-verified this session), Transformer Explainer and LLM Visualization run inference only. This is the main residual risk for claim 1.

### 2. Hand-written WGSL training with gradient parity

- TabGPT README: "`src/engine/kernels.ts`: every op as hand-written WGSL, forward and backward: embeddings, RoPE, attention, matmuls, RMSNorm, QK-norm, ReLU², softmax cross-entropy, global gradient-norm clipping, AdamW." Its tests are "kernel correctness vs CPU references, end-to-end learning check". Reading `tests/kernels_test.ts` shows checks on the forward matmul and two backward matmuls (`matmulBwdDinp`, `matmulBwdDw`) at `tol = 2e-3` max relative error, then an 80-step loss-decrease test. Nothing is compared against PyTorch.
- webgpu-llm README says the forward pass, backward pass and AdamW all run on the GPU as hand-written WGSL in a browser tab, with every kernel documented line by line at llm.istanbul. No parity claim was read.
- Piston composes gradients from forward ops rather than writing a backward kernel per op (blog), and the blog advises "Just like your tensor operations, make sure you have a way to compare gradients with PyTorch." Test files exist (`crates/piston-core/tests/attn_tests.rs`, `crates/piston-nn/tests/optim.rs`); their contents were not read.
- webgpu-torch (https://github.com/praeclarum/webgpu-torch, 646 stars) is a WebGPU autograd library modeled on PyTorch, so it is a library, not hand-written per-op kernels.
- Meganeura, arXiv 2608.01563 (discovery abstract only, not read in full): native compiler over Vulkan and Metal that "gates forward and backward independently. Forty-eight of 50 device-workload-mode cells pass both gates". Treat as a lead.
- GitHub code search for `backward` in `.wgsl` files turns up many hand-written backward kernels (rullama-framework, clocksmith/doppler, enthropy7/YSCV, MIT-RLX/rlx, MickyBalladelli/OxideLM). Hand-written WGSL backward passes are common in 2026.

### 3. WebGPU training-step breakdown

- 2608.08730 (first part read): "To our knowledge, however, no study characterizes the cost of WebGPU operation dispatch in the context of machine learning inference." It measures 24 to 36 us per dispatch on Vulkan and 32 to 71 us on Metal under Dawn, and shows fusion cutting dispatches from 876 to 564 for a 53% throughput gain. Everything is inference at batch size 1.
- Meganeura abstract: "Dispatch profiles localize the largest gaps to convolution derivatives and attention backward." That is training, but not WebGPU and not in a browser.
- TabGPT says "a training step is a fixed prebuilt dispatch list" with "a three-dispatch optimizer per step", and `tests/step_bench.ts` prints only ms per step and tokens per second. No published breakdown.
- A web search for training-step dispatch counts found only timestamp-query docs. One caveat from that search applies directly. Chrome quantizes timestamp queries to 100 us unless developer features are enabled, which is coarser than a single dispatch. Use 2608.08730's sequential-dispatch method, not raw per-dispatch timestamps.

### 4. Survival analysis; looped vs untied

- 2610.31421 (full text read; copy saved at `research/papers/2610.31421.md`). Omniglot reassigned-label setting with Dense 4L, Dense 12L, Grown b=4 and Loop 4x3: "In Figure 3(b), ICL accuracy emerges earlier for the looped, grown, and four-layer dense models than for the dense 12-layer model." They frame this explicitly as a timing result: "this setting does not differentiate how much ICL is attained but rather the timing and consistency of ICL emergence". Curves are means with standard-error bands "across four (a) and eight (b) smoothed seed trajectories". The language-model arms are single-seed: "All com- parisons use one language-model training seed per arm; evaluation bands do not estimate variation across training runs." The text has 0 mentions of survival, hazard, onset, previous-token heads or two-layer models.
- The confound their own figure exposes is that Dense 4L is also early, so "looped is earlier than dense 12L" may be "fewer unique layers is earlier", not "tying is earlier". The seeds study must separate effective depth from unique-parameter depth.
- 2610.24135 (abstract read): "a looped transformer with a four-layer block iterated eight times solves the task in every seed, while an identically-trained untied transformer of the same effective depth never does, succeeding only with a lower learning rate or supervision of its intermediate layers." Per-seed looped vs untied comparisons exist on other tasks, and the outcome flips with learning rate. A single shared learning rate across arms would bias the hazard ratio.
- 2609.19000 has the censoring concept ("budget-censored (would event with more budget)") but scores forecasts with lead time, Spearman and conformal coverage, not with survival estimators. Its event times span 5,650 to 7,400 steps at fixed config (1.31x spread), so per-arm onset distributions are narrow.
- 2505.17863 (discovery abstract only) reports that "emergence timing follows power laws based on task structure, architecture, and optimizer choice" for sparse attention. A lead to cite as context for architecture-dependent timing.
- Negatives: orx keyword "Kaplan-Meier grokking" returned survival-statistics papers and grokking papers, never both. The one grokking hit (2610.18811) has 0 occurrences of Kaplan, Meier, survival, hazard or censor in its full text. orx keyword "time-to-event analysis of training runs across random seeds" and a web search on Kaplan-Meier curves for emergence returned nothing relevant.

### 5. Gap law across architectures; replication

- 2609.19000 (local copy `research/papers/2609.19000.md` read). The law is post-hoc across 80 valid-anchor runs: anchor at 0.843 of time to emergence, IQR 0.825 to 0.865, range 0.739 to 0.898, frozen envelope t_event in [1.11, 1.36] x t_anchor (fraction 0.735 to 0.901), blind-tested at one new learning rate (5/5). Limitations: "One capability (induction), small models (2-layer fleets; ≤1B public suites), synthetic fleet languages" and "its fraction may yet vary with architecture or capability". Hardware: "one RTX 3080". Training harness is `src/train lm.py` (PyTorch per its name, not confirmed).
- The anchor rule is "alarm at layer-0 previous-token score ≥ 0.10", and the event is "copy advantage ≥ 2 nats, two consecutive evals". In a looped model, layer 0 and layer 1 share weights, so "layer-0 previous-token score" must be redefined per loop iteration. That redefinition is new design and must be frozen before the runs.
- 2606.02378 (abstract read) identifies previous-token and induction heads across Pythia 1B, OLMo 1B and OLMoE at 10 log-spaced revisions. Too coarse for a gap fraction and not per-seed, but it is the closest cross-architecture timing work.
- 2609.15545 (abstract read): in recurrent-global and local-global hybrids, "Carrying concentrates in efficient layers and Matching in global receivers", and "early learning-rate reduction can relocate Carrying and Matching between stages". The previous-token anchor need not be an attention head in every architecture.
- Negatives: orx keyword search on the exact title returned only the paper. A web search for replications, "gap law" or 0.843 found only the paper.

## How to phrase the claim so it survives

1. Do not claim the first browser trainer or the first hand-written WGSL trainer. Sequence Toy (2025), TabGPT (2026-08), webgpu-llm (2026-05) and Little Language Machine (2601.21631) predate this. Credit them in one sentence. The claim that survives is narrower: "a tab that trains a two-layer transformer from random initialization through the induction-head phase change in under a minute on the viewer's GPU, streams previous-token and induction scores live, and lets the viewer ablate heads in the running model." Say "the first we could find" and link this file.
2. Present gradient parity as a correctness guarantee, not a contribution. Publish per-parameter max relative error against PyTorch for every parameter tensor of the full model at initialization and after N Adam steps, on at least two GPU vendors. That is stronger than anything found (TabGPT checks three matmuls against a CPU reference), but do not put the word "first" on it.
3. Frame the systems number as an extension of 2608.08730 from inference to training. "Dispatch count and time split (forward, backward, optimizer) of one WebGPU training step, measured with the sequential-dispatch method of 2608.08730." Name browser, backend (Dawn on Metal or Vulkan, wgpu) and GPU for every number, and say Chrome's 100 us timestamp quantization is why raw timestamps were not used.
4. For the seeds study, claim the method and the population, not the direction. "To our knowledge the first survival analysis (Kaplan-Meier curves and hazard or time ratios with CIs) of induction-head onset across seeds, and the first looped vs untied comparison at 64 seeds per arm in two- to four-layer models." Cite 2610.31421 as the prior finding that looping makes ICL arrive earlier, and position the study as testing it with seeds and a mechanistic onset. Three design choices decide whether this survives review:
   - Separate tying from unique depth. 2610.31421's Dense 4L is also early, so include an untied arm whose unique-layer count matches the looped block, not only one matched in effective depth.
   - Tune the learning rate per arm, or sweep it. 2610.24135 shows the looped vs untied outcome flips with learning rate.
   - Expect near-complete separation. Howe's per-seed spread at fixed config is only 1.31x, so a Cox model may hit monotone likelihood and an infinite hazard ratio. Pre-register an accelerated failure time model (report time ratios) or Firth-penalized Cox as the primary estimator. Report onset in steps, tokens and FLOPs, since a looped arm has fewer parameters per step.
5. For the gap law, split "replicates" from "extends". "Replicates" may be said only if Howe's anchor (layer-0 previous-token score at or above 0.10) and event (copy advantage at or above 2 nats on two consecutive evals) are used verbatim, on a config close to his fleet A (2 layers, width 256, lr 1e-3, batch 64). "Extends" covers the looped and deeper arms. There the per-iteration anchor definition is new and must be frozen before any run. Pre-register the falsifier as an arm median fraction outside Howe's frozen envelope [1/1.36, 1/1.11], that is 0.735 to 0.901. Say "the first independent test we found" and note that 2609.19000 has had little attention, so priority here is cheap.
6. Call the record table what it is. "A public table of wall-clock time to the induction event in a browser tab on the submitter's own hardware, in the spirit of the NanoGPT speedrun record table." Store `GPUAdapterInfo`, browser, backend, step count and a run hash with each row. Mark self-reported rows as unverified. Volume Shader's withdrawn WebGPU claims show what happens without backend provenance.
7. Residual risk to state honestly. These were not searched one by one: Transformer Explainer, LLM Visualization, TensorFlow.js examples, ONNX Runtime Web training, Observable notebooks, surfgrad, TinyGPT and jax-js. One more targeted pass on those before publishing would close the main gap in claim 1.
